About PhishGuard AI

API: checking...

PhishGuard AI reads the text of an email and says whether it looks like phishing, how likely that is, and which words pushed it to that answer. It is meant to help a person sort reported emails quickly: it ranks and explains, and a person still decides. It does not look at attachments, sender addresses or the links themselves.

It was built for the ITRI625 Machine Learning project at North-West University (2026) by Lwazi Nhlapo and Colile Sibanda. The sections below go from a short overview to the full technical detail.

How the parts connect

One trained model, one API in front of it, and two ways to use it. Both clients get the same answer because both call the same API.

  1. Data (offline): the public Kaggle phishing email dataset (about 82 000 emails) is cleaned, exact duplicates are removed, and it is split 70/15/15 into training, validation and test sets.
  2. Training and evaluation (offline, in the Jupyter notebook): a TF-IDF and logistic regression baseline and a 1D convolutional network are trained; the network uses early stopping; the decision threshold is chosen on validation data; the test set is scored once at the end.
  3. The API (FastAPI): loads the saved network once at start-up and answers /predict, /explain, /health, /model-info and /metrics.
  4. The clients: this browser UI and the Tkinter desktop app both call the API over HTTP.
  5. Hosting: the Dockerfile runs the API and this UI in one container, so the same build runs locally or on a cloud host.
What happens when you click Analyse email
  1. The page sends your text to POST /predict and shows the verdict as soon as it returns, then sends it to POST /explain for the word weights.
  2. The security layer checks the request rate for your address and, for explanations, the rate across all users. Over the limit the answer is HTTP 429 with a Retry-After header.
  3. The request schema rejects empty text and text over 200 000 characters with HTTP 422, naming the email_text field.
  4. Inside the model, a TextVectorization layer splits the text on spaces and maps each word to its index in a 30 000-word vocabulary learned from the training set, cut or padded to 300 words.
  5. The network returns one number: the probability that the email is phishing. At or above 0.54 the verdict is phishing.
  6. For the explanation, LIME builds 1 000 copies of the email with words removed at random, scores them all, and fits a small linear model; its weights are the influence of each word.
  7. The page underlines those words in your text and lists them with their weights.

Technical details

One section per part of the system. Each says what it does, why it is built that way, and where the code is.

Data and splits

The dataset is the Kaggle Phishing Email Dataset (naserabdullahalam/phishing-email-dataset), a pool of public collections with each email labelled 1 for phishing and 0 for legitimate. Exact duplicate rows are removed (408 of 82 486), then the data is split with a fixed seed (42) and stratified by label into 57 453 training, 12 312 validation and 12 312 test emails, so each set keeps the same share of phishing.

The raw and processed CSV files are not in the repository because of their size; the notebook rebuilds the splits from data/raw/phishing_email.csv. Code: notebooks/phishing_detection.ipynb.

The model: a 1D convolutional network

Layers, in order: TextVectorization (30 000 words, 300 per email), Embedding (64 dimensions per word), SpatialDropout1D (0.2), Conv1D (128 filters of width 5, ReLU), GlobalMaxPooling1D, Dense (128, ReLU), BatchNormalization, Dropout (0.3), Dense (64, ReLU), Dropout (0.3), and a single sigmoid output.

Why this shape: a filter of width 5 learns short phrases such as "verify your account", and global max pooling keeps the strongest match wherever it appears in the email, which suits phishing cues that can sit anywhere in the text. Dropout and early stopping limit overfitting.

Training: Adam (learning rate 0.001), binary cross-entropy, batches of 256, at most 20 epochs. Early stopping watches validation loss with a patience of 3 and restores the best weights; the learning rate halves when validation loss stalls for 2 epochs. Accuracy, precision, recall, F1, ROC-AUC, PR-AUC and loss are logged every epoch to outputs/metrics/deep_learning_training_log.csv.

The baseline is TF-IDF (single words and pairs, 50 000 features) with logistic regression, scored on the same splits for comparison.

Threshold and evaluation

The cut-off between phishing and legitimate (0.54) was chosen by F1-score on the validation set and frozen in models/deep_learning/decision_config.json before the test set was used. The test set was scored once with that frozen model and threshold; the results are in outputs/metrics/ and on the Model page.

Explanations (LIME)

LIME (Local Interpretable Model-agnostic Explanations) treats the network as a black box. It perturbs one email by removing words, scores every copy, and fits a weighted linear model to those scores. A positive weight means the word pushed the probability towards phishing. It explains one prediction locally and is not proof of what the model learned overall. Code: api/predictor.py.

The API

FastAPI, in api/main.py. The model and threshold load once when the process starts, not per request. Endpoints: GET /health, GET /model-info, GET /metrics, POST /predict, POST /explain. Interactive documentation is at /docs. This UI is served from web/ at /ui/.

Security

Code: api/security.py. Every response carries security headers (no MIME sniffing, no framing, no referrer). This UI gets a Content Security Policy that allows only its own files: no third-party script, style or font. Scoring requests are limited per client (30 a minute, 6 explanations a minute) and across all users (30 explanations a minute), and at most 2 explanations run at once, because each one scores 1 000 copies of the email. Errors return a short message and never internal details.

Desktop app

Tkinter, in desktop_app/app.py. It calls the same API over HTTP on a background thread so the window never freezes. Set PHISHGUARD_API_URL to point it at a hosted copy instead of the local one.

Testing and running it

Tests in tests/ check the endpoints, the input validation, the security headers, the rate limits and the threshold logic: run run_tests.bat or pytest -q. To run everything on Windows: setup.bat once, then start_all.bat.
